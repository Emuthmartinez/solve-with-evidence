# Completion conformance protocol

Freeze the prompts, outcome oracle and grader before dispatch. Deliver the first two recovery snapshots, collect the response, then deliver the two later replays. The solver sees the assigned skill version and the requested stage only. Both arms receive the same request and signed evidence. The reserved case changes the domain, IDs and order of presentation. It probes transfer within this family.

## Primary endpoint

Each of four snapshots earns one point for an exact trace from all currently mandatory signed order items to the qualifying registered goals, one for the binding stop receipt, and two for the notification decision. Sixteen points and zero unsupported releases constitutes a pass. An exact trace requires the complete original obligation set adjusted for signed amendments. An optional goal does not discharge an obligation under this explicitly stated host contract. The oracle separately checks request coverage and the stop event. It does not derive either from the status flags that the coordinator set. An unsupported release is a critical failure. A blanket hold loses the genuine completed case. No wording in rationale is scored.

## Predicate diagnostic

The historical reference is source commit 6debdca, in the numbered completion predicate and final transition in the scheduling pseudocode. Condition 1 requires an explicit goal. Its quantifier over required goals permits an empty required set. Condition 3 requires usable deliverables and does not specify whether their source is the original order or the imported register. The pseudocode restricts dispatch on cancellation and then evaluates the completion predicate and quiescence independently. The skill also requires evaluation against original goals and recognizes current authorization. A reader can enforce those wider duties in the numbered conditions.

The fixture implements one concrete, documented registry-local interpretation of those underspecified domains. It demonstrates a possible false-positive implementation of this specification. It cannot establish that every faithful implementation fails or that the host running a live application uses this interpretation. For each stage, collect the solver's interpretation of the actually loaded version (permits, blocks, or ambiguous) and its evidence. Record it alongside the old adapter's output, outside the primary score. A changed skill can properly give different answers on this diagnostic. Count an improved document-level guard only when a reviewer can point to its actual domain, event check and control flow. A changed solver answer alone is insufficient.

## Controls and scope

Run `python3 -B closure.py` to verify the original-order oracle and adapter mutations, cancellation removal, required-flag change, removed obligation, authorized supersession, and a stop for another run. Cases use synthetic, complete in-memory observations. They test release judgments and a proposed predicate implementation. They do not exercise a live scheduler, race protection, or an external notification endpoint.
